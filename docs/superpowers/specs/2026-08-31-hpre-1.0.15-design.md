# HPre 1.0.15 Technical Specification & Design Document

- **Target Version:** 1.0.15 (Version Code: 16)
- **Baseline Version:** 1.0.14 (Version Code: 15)
- **Primary Focus:** Video Open Performance & Metrics Breakdown, Adaptive Fullscreen & Safe Insets, Robust Player Lifecycle Management, and Release Readiness.

---

## 1. Problem Statement & Objectives

In HPre 1.0.14, while baseline ABR and root navigation were stabilized, opening videos can experience minor latency variations, duplicate requests when rapidly jumping across related videos, and edge-case overlay overlaps on modern notched/cutout displays.

**Core Goals for 1.0.15:**
1. **Performance Metrics & Bottleneck Identification**:
   - Accurately measure and log duration across all phases: Tap -> Extractor -> Network/MediaSource -> Player Prepare -> First Frame Rendered.
   - Profile performance on cold-cache, warm-cache, and slow network connections.
2. **Video Startup Optimization**:
   - Strictly enforce a single, non-redundant pipeline per video transition: Resolve Stream Info -> `setMediaSource()` -> `prepare()`.
   - Prevent duplicate network calls; instantly cancel and clean up in-flight jobs from prior videos when switching items quickly.
   - Maintain seamless Player / Watch ViewModel reuse across screen rotation and fullscreen toggle without rebuilding ExoPlayer or MediaSource.
   - Prevent loading spinner flickering by coordinating the loading state directly with the first rendered frame.
3. **Adaptive Device Fullscreen & Window Insets**:
   - Implement `RESIZE_MODE_FIT` aspect ratio containment on the playback surface so all aspect ratios (16:9, 18:9, 19.5:9, 20:9, 4:3, square 1:1, vertical Shorts) retain their natural proportions without cropping or distortion.
   - Ensure Player overlay controls adapt to status bars, navigation bars, and display cutouts (notches / punch-hole cameras) across portrait and landscape orientations.
4. **Regression & Stability Guarantees**:
   - Maintain the A -> B -> C -> D -> Back -> Home navigation flow established in 1.0.14.
   - Prevent memory leaks, zombie coroutine jobs, and stale surface attachments.
5. **Release Verification**:
   - Version bump to `1.0.15` (`versionCode = 16`).
   - Validate release keystore fingerprint and unit/instrumentation tests.

## 2. Architecture & Detailed Module Design

### 2.1 Video Open Metrics & Bottleneck Breakdown
We will refine `com.hpre.app.core.performance.VideoOpenMetrics` to capture fine-grained milestones:
- `VIDEO_OPEN_START`: Instant user clicks video item in Home / Search / Related.
- `DETAILS_READY`: Video metadata (title, channel info, etc.) loaded from cache or network.
- `STREAM_INFO_READY`: Extractor has fetched stream URLs & available qualities.
- `PLAYER_PREPARE`: Controller dispatches prepare command with target MediaSource.
- `PLAYER_READY`: ExoPlayer transitions to `Player.STATE_READY`.
- `FIRST_FRAME`: `AnalyticsListener.onRenderedFirstFrame()` fires on the video renderer.

```
User Click (VIDEO_OPEN_START)
   │
   ├─► Catalog / VideoService Fetch ─► DETAILS_READY
   │
   ├─► Stream Info Extractor ────────► STREAM_INFO_READY
   │                                        │
   │                                        ▼
   └─► PlayerController.prepare() ───► PLAYER_PREPARE
                                            │
                                            ▼
                                       PLAYER_READY
                                            │
                                            ▼
                                       FIRST_FRAME (Finish Session)
```

### 2.2 Video Loading Pipeline & Cancellation Optimization
- **`WatchViewModel` Request Pipeline**:
  - Maintain `currentGeneration` and `sessionGuard` synchronization.
  - When `load(key)` is invoked for a new video, all active coroutines (`loadJob`, `relatedJob`, `commentsJob`, `commentsGateJob`) are immediately cancelled.
  - `PlayerController.stopForTransition()` resets the current media session without dropping the underlying `MediaController` connection.
  - `VideoService.streamInfo(key)` and metadata fetching execute strictly on `Dispatchers.IO`.
  - The loading indicator overlay remains active until either `renderedFirstFrameCount > 0` or `isReady && !isBuffering`.

### 2.3 Single Shared Player & ViewModel Across Config Changes
- `WatchScreen` avoids destroying or recreating playback state across orientation changes:
  - `Activity` orientation changes and fullscreen state changes reuse the single `WatchViewModel` (scoped to the navigation backstack entry or retained across configuration changes).
  - Surface handoff via `PlaybackUiCoordinator` and `SurfaceLease` ensures `PlayerView` attachment seamlessly transfers when entering/exiting fullscreen.
  - Media3 Adaptive Bitrate (ABR) is preserved as the default policy (`UserQualityPolicy.Auto`) without forced track switching during UI transitions.

### 2.4 Adaptive Fullscreen & Safe Cutout Insets
- **Player Surface Sizing**:
  - Configure `PlayerView` inside `PlayerSurface.kt` with `resizeMode = AspectRatioFrameLayout.RESIZE_MODE_FIT`.
  - In non-fullscreen portrait: container maintains 16:9 or auto-adjusts to video ratio with `Modifier.fillMaxWidth().aspectRatio(...)`.
  - In fullscreen mode: `Modifier.fillMaxSize().background(Color.Black)`, with video centered and fitted preserving aspect ratio; black bars appear naturally on letterboxed/pillarboxed edges without stretching or zooming.
- **Controls & Inset Handling**:
  - Status bar / navigation bar controls handled by `DefaultWindowSystemUiController` via `WindowInsetsControllerCompat`.
  - In `PlayerControlsOverlay`, control rows (top header, center buttons, bottom progress bar) apply `Modifier.displayCutoutPadding()` and `Modifier.systemBarsPadding()` where appropriate so that notch/camera cutouts do not overlap interactable elements (e.g. Back button, Settings menu, Seek slider).

## 4. Risks & Mitigations

- **Risk**: Video playback glitching or surface detachment during quick fullscreen toggles.
  - *Mitigation*: Leverage existing generation-based `SurfaceLease` coordinator to cleanly attach/detach the surface without restarting the player.
- **Risk**: Layout clipping on non-standard aspect ratio screens (e.g., foldable or 21:9 devices).
  - *Mitigation*: Using `RESIZE_MODE_FIT` ensures ExoPlayer scales to the inner rectangle bounds without cropping video edges.
