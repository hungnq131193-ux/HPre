# HPre 1.0.35 Android Form Factors Design

## Goal

Ship the existing HPre 1.0.35 release as one Android APK that remains usable on
touch tablets, Android TV devices, and standard Android car displays. Keep the
existing application ID, release signing identity, playback stack, provider,
local data, and version `1.0.35` unchanged.

## Scope

In scope:

- Make touch input optional in the manifest so TV and car hardware can install
  the APK.
- Add the Android TV launcher entry and optional device capability declarations
  without excluding phones or generic Android car displays.
- Detect remote-oriented devices from platform features and make custom
  clickable Compose content focusable with a visible focus treatment.
- Preserve D-pad, keyboard, Back, and touch activation for primary navigation,
  feed cards, search results, library rows, settings rows, and playback actions.
- Constrain non-player content on very wide displays while keeping the Watch
  player full-width and preserving its 16:9 behavior.
- Add deterministic unit coverage for platform-mode selection and adaptive
  content policy, then build and inspect the signed release APK.

Out of scope:

- Android Auto templates, `androidx.car.app`, or a separate Android Automotive
  OS browsing experience. The requested car target is a standard Android
  display that can install APK files.
- A second APK, product flavor, ABI split, or new runtime dependency.
- Changes to video extraction, Media3 playback recovery, provider selection,
  local persistence, or release versioning.
- A full TV-specific redesign or a multi-column catalog. The existing screens
  remain the source of truth; only input and wide-display constraints change.

## Design

### 1. Device input policy

Add a small pure policy in the UI/platform package. It receives three platform
facts: whether the device advertises Leanback, whether it advertises the
automotive feature, and whether it has a touchscreen. Remote mode is selected
when Leanback or automotive is present, or when no touchscreen is present.
Touch mode remains the default for ordinary phones and tablets.

The Compose root reads the policy once from `PackageManager` and provides the
result through a composition local. This avoids threading a device flag through
every screen and keeps the policy unit-testable without Android instrumentation.

### 2. Focusable activation

Create one adaptive modifier for custom clickable surfaces. In touch mode it
retains the current clickable behavior. In remote mode it also adds Compose
focusability, keyboard/D-pad activation semantics, and a bounded high-contrast
focus border. Replace direct custom `.clickable` uses in feed cards, result
cards, library rows, settings rows, suggestions, recent searches, and playlist
rows with this modifier.

Material buttons, chips, switches, sliders, and icon buttons remain Material
controls and keep their existing semantics. Add only the minimum focus grouping
needed for horizontal chip rows and card collections; let Compose's standard
directional focus search handle movement between controls. Existing content
descriptions and test tags remain unchanged.

### 3. Wide-display host

Wrap non-Watch navigation content in a centered host with a maximum content
width of `1200.dp` and safe horizontal padding. On phone and tablet widths this
host fills the available space. On very wide TV/car displays it prevents
unreadably long rows and excessive thumbnail scaling.

The Watch route bypasses the max-width host so the player and fullscreen surface
remain full-bleed. Existing player aspect-ratio and system-inset handling stay
unchanged.

### 4. Manifest and launcher

Update `app/src/main/AndroidManifest.xml` with optional features:

- `android.hardware.touchscreen` with `required="false"`;
- `android.software.leanback` with `required="false"`;
- `android.hardware.type.automotive` with `required="false"`.

Keep the normal `MAIN`/`LAUNCHER` entry and add a separate
`MAIN`/`LEANBACK_LAUNCHER` entry for TV launchers. No automotive-specific
launcher category is added, because generic Android car displays use their
normal launcher and the scope does not include Android Auto/Automotive OS
templates. Add a simple TV banner resource if the existing adaptive icon is not
accepted as a TV launcher banner by static validation.

### 5. Release integrity

The feature branch starts at tag `v1.0.35` and continues to use:

- package `com.hpre.app`;
- `versionName = "1.0.35"`;
- `versionCode = 36`;
- the existing HPre release keystore and certificate;
- the existing minified and resource-shrunk release configuration.

No tag, GitHub release, or replacement of the existing root APK is part of this
change. The candidate is emitted with a temporary verification name outside
tracked source, then its package, version, manifest features, signature, and
SHA-256 are inspected.

## Error handling and compatibility

- Missing or unusual hardware feature declarations must fall back to touch
  mode only when a touchscreen is present; an input-less device remains in
  remote mode so it is not left with non-focusable content.
- Focus decoration must not change click callbacks, navigation routes, player
  ownership, or persistence behavior.
- The wide host must not clip content, dialogs, system bars, PiP, or fullscreen
  playback.
- Existing network, extraction, playback, and persistence errors continue to
  use their current user-visible error panes and retry paths.
- The release build must fail normally on signing or lint errors; no bypass,
  warning suppression, or debug signing is allowed.

## Verification

Before implementation, the baseline `v1.0.35` worktree must pass the existing
unit test task. After implementation, run:

```text
gradlew.bat --no-daemon :app:testDebugUnitTest
gradlew.bat --no-daemon :app:lintDebug
gradlew.bat --no-daemon :app:assembleDebug :app:assembleDebugAndroidTest :app:assembleRelease
```

Inspect the release APK with SDK `aapt`/`apkanalyzer` and `apksigner` for the
package, version, optional features, both launcher categories, and the same HPre
certificate as the `v1.0.35` baseline. If an Android emulator is available,
install the candidate without uninstalling the app and smoke test launch, D-pad
focus/navigation, Back, search, and Watch entry. Record that an emulator is not
a TV/car hardware substitute when only a standard phone AVD is available.

The automated regression check must cover:

- Leanback, automotive, no-touchscreen, and ordinary touchscreen mode choices;
- the wide host max-width and Watch full-width split;
- existing unit tests and release build configuration at `1.0.35`.

## Risks and ceiling

The repo has no attached physical TV, tablet, or car display in the current
environment, so physical OEM launcher, remote key mapping, overscan, and audio
focus behavior cannot be proven locally. The implementation will therefore
provide deterministic policy tests, static APK checks, and emulator smoke tests
where available.

`ponytail:` This delivery stops at one adaptive standard-Android APK. Add
device-specific layouts or Android Auto/Automotive OS templates only after a
real target device exposes a behavior that the adaptive host cannot support.
