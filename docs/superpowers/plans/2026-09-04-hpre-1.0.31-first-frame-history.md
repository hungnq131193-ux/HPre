# HPre 1.0.31 First-Frame and Watch-History Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release HPre 1.0.31 with a median tap-to-`FIRST_FRAME` improvement of at least 15 percent over an equivalently instrumented 1.0.30 baseline, while retaining only the 50 newest unique watch-history videos.

**Architecture:** Keep one `StreamInfo` object on the critical path from extractor cache through Watch, the app-scoped controller, the in-process handoff, and the playback service. Cancel nonessential Home/Search work at selection time, perform Home disk-cache work on IO, make prewarm retries bounded and reusable, and trim watch history transactionally without touching search history or `PlaybackSnapshotStore`. Land measurement-only commits before behavior changes so the same instrumentation can be cherry-picked onto `v1.0.30` for the release benchmark.

**Tech Stack:** Kotlin, Coroutines/Flow, Jetpack Compose, Room, AndroidX Media3/ExoPlayer, NewPipeExtractor, OkHttp, Gradle, PowerShell, Android SDK API 35, GitHub REST API.

**Spec:** `docs/superpowers/specs/2026-09-04-hpre-1.0.31-first-frame-history-design.md`

- [ ] **Step 3: Implement the metric state machine**

Use one pending tap and one active session. `startTap` retires any pending tap and active session before creating a new pending session. `claimTap` claims only matching key once and transitions the exact pending session to active. `start` is for direct navigation/retry and retires previous state. `cancel` retires the session whether it is pending or active and ensures no subsequent records or events can be emitted. Duplicate marks for the same event must be silently ignored and cannot overwrite the initial timestamp. Metric records must never contain content key, title, URL, query parameters, headers, cookies, token, body, or raw exception strings. Store the first timestamp for each event and attach a duration only to the three endpoint events.

```kotlin
enum class VideoOpenEvent {
    VIDEO_OPEN_START,
    STREAM_RESOLVE_START,
    EXTRACTOR_START,
    EXTRACTOR_FINISH,
    DETAILS_READY,
    STREAM_INFO_READY,
    PLAYER_PREPARE,
    PLAYER_READY,
    FIRST_FRAME,
    PLAYBACK_ERROR
}

enum class VideoOpenSegment {
    STREAM_RESOLVE_TO_STREAM_INFO_READY,
    STREAM_INFO_READY_TO_PLAYER_PREPARE,
    PLAYER_PREPARE_TO_FIRST_FRAME
}

data class VideoOpenRecord(
    val generation: Long,
    val event: VideoOpenEvent,
    val elapsedMs: Long,
    val segment: VideoOpenSegment? = null,
    val segmentMs: Long? = null,
    val category: String? = null
)
```


Map endpoints exactly as follows:

```kotlin
private fun segmentFor(event: VideoOpenEvent): Pair<VideoOpenSegment, VideoOpenEvent>? = when (event) {
    VideoOpenEvent.STREAM_INFO_READY ->
        VideoOpenSegment.STREAM_RESOLVE_TO_STREAM_INFO_READY to VideoOpenEvent.STREAM_RESOLVE_START
    VideoOpenEvent.PLAYER_PREPARE ->
        VideoOpenSegment.STREAM_INFO_READY_TO_PLAYER_PREPARE to VideoOpenEvent.STREAM_INFO_READY
    VideoOpenEvent.FIRST_FRAME ->
        VideoOpenSegment.PLAYER_PREPARE_TO_FIRST_FRAME to VideoOpenEvent.PLAYER_PREPARE
    else -> null
}
```

Keep the log format machine-parseable:

```text
EVENT generation=N elapsedMs=N segment=SEGMENT segmentMs=N category=CATEGORY
```
