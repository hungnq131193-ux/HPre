# HPre 1.0.4 Performance and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Collapse duplicate video-page extraction, move non-playback work behind player prepare, preserve cached Watch content, avoid eager player startup, add debug timing, and produce a verified HPre 1.0.4 release candidate.

**Architecture:** One NewPipe stream-page extraction maps an `ExtractedVideoBundle`; a bounded 20-second single-flight coordinator in `NewPipeVideoService` shares that bundle across details, stream, and related consumers. `WatchViewModel` starts stream/details/resume together and admits related/comments only after prepare, while existing caches and generation guards remain authoritative. Existing player selection, network policy, Compose lists, and storage architecture stay unchanged.

**Tech Stack:** Kotlin, coroutines, JUnit 4, Android Gradle Plugin, Jetpack Compose, Media3/ExoPlayer, NewPipeExtractor, OkHttp, Room, DataStore, PowerShell 5.1, Android SDK build tools, Git, GitHub.

**Spec:** `docs/superpowers/specs/2026-08-28-hpre-1.0.4-performance-release-design.md`

## Global Constraints

- Keep application ID and namespace exactly `com.hpre.app`.
- Keep NewPipeExtractor; do not add a backend or API.
- Preserve background playback, PiP, resume, history, playlists, subscriptions, search, recommendations, comments, quality selection, stream recovery, update checker, and existing caches.
- Bundle success TTL is exactly 20,000 ms and capacity is exactly 16 entries.
- Keep extractor network policy at connect/read/call 15/20/30 seconds.
- Do not change Media3 buffer sizes, stream muxing, startup selector, or quality escalation.
- Do not add dependencies.
- Use TDD: observe each new test fail before production code.
- Never generate a signing key or alias.
- Never print, commit, upload, or stage keystores, passwords, API keys, tokens, credentials, `local.properties`, APK build intermediates, or secret-bearing files.
- Do not push if `test`, `assembleDebug`, or `assembleRelease` fails.
- Push only `perf/hpre-1.0.4`, create a PR into `main`, and do not merge it.
- Do not create tag `v1.0.4` or GitHub Release before user merges the PR.

```kotlin
override fun videoBundle(key: ContentKey): ExtractedVideoBundle {
    return videoBundleLoader(streamingService, key, serviceId)
}

private fun loadVideoBundle(
    service: StreamingService,
    key: ContentKey,
    serviceId: Int
): ExtractedVideoBundle {
    val handler = service.streamLHFactory.fromId(key.nativeId)
    val extractor = service.getStreamExtractor(handler)
    extractor.fetchPage()
    val info = ExtractorStreamInfo.getInfo(extractor)
    val details = NewPipeMappers.mapVideoDetails(info, serviceId)
        ?: throw ExtractionException("Failed to map valid video details")
    val streams = NewPipeMappers.mapStreamInfo(info, serviceId)
        ?: throw ContentNotSupportedException("No usable playback streams or manifests found")
    if (details.key != key || streams.key != key) {
        throw ExtractionException("Returned video key does not match requested key $key")
    }
    val related = info.relatedItems.orEmpty()
        .filterIsInstance<org.schabi.newpipe.extractor.stream.StreamInfoItem>()
        .mapNotNull { NewPipeMappers.mapStreamInfoItemToSummary(it, serviceId) }
    return ExtractedVideoBundle(details, streams, related)
}
```

Delete old duplicate overrides of `video()`, `streamInfo()`, and `related()` from `DefaultExtractorOperations`; interface defaults project from `videoBundle()`. Do not cache raw NewPipe objects. Existing test doubles that override one old projection remain source-compatible until Task 2 migrates service integration tests.
