# HPre 1.0.10 Reliability Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the 1.0.8/1.0.9 playback reliability regressions and prepare the signed HPre 1.0.10 release branch.

**Architecture:** Snapshot finalization becomes an in-memory update plus generation-guarded background DataStore write, so service teardown never waits for storage. Existing bounded components retain their designs while their prior capacity limits are restored; Media3 buffering is tuned in the playback service. `SessionPlayerController` starts a connection when a prepare arrives after the controller has been cleared, preserving its existing pending-command drain and generation guards.

**Tech Stack:** Kotlin, coroutines, Android DataStore, Media3, JUnit4, Gradle, GitHub CLI.

**Spec:** `docs/superpowers/specs/2026-08-30-hpre-1.0.10-reliability-release-design.md`

## Global Constraints

- Branch from `origin/main` as `perf/hpre-1.0.10-reliability`; retain application ID `com.hpre.app` and release minification.
- Do not add dependencies, a cache framework, an unbounded executor, a timeout/retry rewrite, a benchmark module, or a fixed startup-time SLA.
- Preserve latest-generation-wins snapshot semantics; persistence failures remain non-fatal and must not block lifecycle or service teardown.
- Keep Watch stream and resume concurrent; related/comments remain after `playerController.prepare()`.
- Use only existing `hpreSigning.*` Gradle properties or `HPRE_SIGNING_*` environment variables. Never generate, copy, print, or commit signing material.
- Set `versionCode = 11`, `versionName = "1.0.10"`, and name the verified release asset `HPre-v1.0.10.apk`.
- Do not tag or create a GitHub Release until the PR is merged into `main`.
