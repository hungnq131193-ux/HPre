# FlowTube V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an installable native Android FlowTube V1 that searches public provider content through an isolated NewPipeExtractor adapter and plays supported streams with a single resilient Media3 session.

**Architecture:** A single Android application module has strict Kotlin package boundaries. Compose UI calls ViewModels and repositories; repositories consume the provider-neutral `VideoService`; `NewPipeVideoService` is the only code importing NewPipeExtractor. A `MediaSessionService` owns the only `ExoPlayer`; UI controls it through a lifecycle-aware Media3 controller.

**Tech Stack:** Kotlin, Gradle Kotlin DSL, Android Gradle Plugin, Jetpack Compose/Material 3, Coroutines/Flow, AndroidX Navigation, Media3/ExoPlayer, Room/KSP, DataStore, Coil, OkHttp, NewPipeExtractor, JUnit and AndroidX test.

**Spec:** `docs/superpowers/specs/2026-08-24-flowtube-design.md`

## Global Constraints

- Application ID is exactly `com.flowtube.app`; do not use `youtube`, `google`, or `newpipe` in the application ID/package.
- `minSdk` is 26; choose and lock compatible stable JDK, Gradle, AGP, Kotlin, Compose BOM/compiler plugin, Media3, Room/KSP, Coil, OkHttp and NewPipeExtractor versions at the build gate.
- No official source-platform API/player SDK, WebView playback, Google Play Services core dependency, login, downloader, advertising, analytics, cloud sync, backend, or source-account mutation.
- Do not copy source-platform branding, artwork, names, logos, or exact brand palette. Local user actions must be labelled local.
- Only `extractor/` imports NewPipeExtractor. `model/` imports neither Android UI/database/player APIs nor extractor APIs.
- All extractor/network/database work is structured, cancellable and off Main; do not use `GlobalScope` or block the Main thread.
- One `ExoPlayer` exists per active playback service session; never instantiate a player per card or screen.
- Do not persist direct stream URLs. Do not bypass DRM, paywall, CAPTCHA, login, age, geographic, or other access controls.
- User-visible errors are domain errors, never raw Java exceptions. Retry is finite and cancellable.
- Workspace is not a Git repository; do not attempt commits. Run the stated verification commands at each task gate.

- [ ] **Step 4: Implement synchronous-extractor boundary and exception mapping.**

Every `VideoService` method uses `withContext(Dispatchers.IO)` and maps cancellation by rethrowing `CancellationException`. Map offline/timeout, HTTP status, source restriction exceptions, parsing failures and unknown exceptions to `AppError`; do not use `runCatching` in a way that catches cancellation.

```kotlin
private suspend fun <T> extract(block: () -> T): AppResult<T> = withContext(ioDispatcher) {
    try { AppResult.Success(block()) }
    catch (cancelled: CancellationException) { throw cancelled }
    catch (error: Throwable) { AppResult.Failure(mapExtractorFailure(error)) }
}
```
