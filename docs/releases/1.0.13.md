## Thay đổi

1. **Bộ đệm byte video LRU 64 MiB (chuẩn NewPipe):**
   - Thêm lớp cache Media3 `SimpleCache` (64 MiB, fragment 2 MiB, `FLAG_IGNORE_CACHE_ON_ERROR`) tại `cacheDir/video_cache`.
   - Áp dụng cho các luồng `PROGRESSIVE` non-live và hai track của `MERGED_AV` non-live.
   - `AUDIO_ONLY`, `DASH`, `HLS` và mọi livestream không qua cache byte.
2. **Khóa cache ổn định độc lập với URL ký:**
   - Mở rộng model `VideoStream` (`streamId`, `deliveryMethod`) và `AudioStream` (`streamId`, `audioTrackId`).
   - `YouTubeCacheKeyFactory` tạo key phân biệt track theo `streamId`, format, resolution, audioTrackId, language; chỉ lưu digest SHA-256 vào cache index.
   - Fallback băm SHA-256 toàn bộ URL chỉ khi extractor không cung cấp stream ID hợp lệ.
3. **Adapter Media3 chuyển tiếp YouTube (3 Request Profiles):**
   - Profile `DASH`: thêm tham số `rn`, chuyển `Range` header thành query parameter `range` cho `/videoplayback`.
   - Profile `PROGRESSIVE`: thêm tham số `rn`, giữ nguyên `Range` header.
   - Profile `HLS`: không thêm `rn` hoặc query parameter `range`.
   - Bổ sung các header theo chuẩn NewPipe (`Origin`, `Referer`, `Sec-Fetch-*`, `TE`) và gửi request `POST` với body `{ 0x78, 0x00 }` cho YouTube endpoints.
   - Chuyển tiếp 302 theo ngữ nghĩa OkHttp (POST sang GET không body) và xử lý HTTP 416 tại EOF đúng chuẩn.
4. **Nút "Xóa bộ nhớ đệm video" trong Settings:**
   - Thêm mục và dialog xác nhận xóa dữ liệu cache video an toàn trên Dispatchers.IO. Không xóa cache ảnh Coil hay metadata.

## Kiểm tra và build

JDK 17 có javac, Android SDK platform 35 và build-tools 35.0.0. Dùng Gradle wrapper của repository.

```powershell
$env:ANDROID_HOME = "C:\Users\HUNG\AppData\Local\Android\Sdk"
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest --no-daemon
.\gradlew.bat connectedDebugAndroidTest --no-daemon
```

Build signed release bằng key HPre hiện có:

```powershell
.\gradlew.bat assembleRelease --no-daemon
```
